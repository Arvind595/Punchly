## v19 · Future leave and employee details

**Evidence.** v19 release marker, with its own source snapshot. [`5e1b98c`](https://github.com/Arvind595/Punchly/commit/5e1b98c46a3f36d1c356c0490789044c06370341) · [Diff 7316471 → 5e1b98c](https://github.com/Arvind595/Punchly/compare/73164717076339aa4a8ed71ebfd0ac7b0f1345c5...5e1b98c46a3f36d1c356c0490789044c06370341)

- **Future dates.** Dates can move to future months. The date selection UI shows whether leave is available to reserve, update or cancel. The app validates the requested date and existing entry before writing a daily leave record. Reservations live with attendance records and can be edited without inventing punches or worked minutes. [Date actions](https://github.com/Arvind595/Punchly/blob/5e1b98c46a3f36d1c356c0490789044c06370341/js/attendance.js#L47) · [Reservation write](https://github.com/Arvind595/Punchly/blob/5e1b98c46a3f36d1c356c0490789044c06370341/js/app.js#L561) · [Reservation removal](https://github.com/Arvind595/Punchly/blob/5e1b98c46a3f36d1c356c0490789044c06370341/js/app.js#L581)
- **Profile and reporting.** `Storage.profileDetails` normalizes display name, employee ID, email, role and department. Exports use a profile dialog and pass the selected fields into the report metadata. Follow `employeeLines` to see which fields appear visually in reports. Later v30 narrows when the prompt opens. [Field normalization](https://github.com/Arvind595/Punchly/blob/5e1b98c46a3f36d1c356c0490789044c06370341/js/storage.js#L106) · [Profile dialog](https://github.com/Arvind595/Punchly/blob/5e1b98c46a3f36d1c356c0490789044c06370341/js/export.js#L26) · [Rendered metadata](https://github.com/Arvind595/Punchly/blob/5e1b98c46a3f36d1c356c0490789044c06370341/js/export.js#L70)
- **Assets and reproduction.** The same snapshot bundles offline Playpen Sans, Nunito and Comic Neue and tightens Compact mode. The historical fixture filenames contain `v18`, while Git first records them here. Use them to reproduce historical backup and export behavior in an isolated profile. [Bundled fonts](https://github.com/Arvind595/Punchly/blob/5e1b98c46a3f36d1c356c0490789044c06370341/css/style.css#L5) · [`README.md`](https://github.com/Arvind595/Punchly/blob/5e1b98c46a3f36d1c356c0490789044c06370341/test-data/README.md) · [`Punchly_v18_test_backup.json`](https://github.com/Arvind595/Punchly/blob/5e1b98c46a3f36d1c356c0490789044c06370341/test-data/Punchly_v18_test_backup.json)

## v23 · UISFX integration and tests

**Evidence.** v23 release marker and archived note. [`3a430e7`](https://github.com/Arvind595/Punchly/commit/3a430e74f62595f8dbdbb25f19d7e8fb59c410ef) · [Archived v23 note](https://github.com/Arvind595/Punchly/blob/3a430e74f62595f8dbdbb25f19d7e8fb59c410ef/index.html#L407)

- **Build boundary.** Sound introduces a Node development toolchain. `src/ui-sounds.ts` is the authoring source, `package.json` defines the build, and `vendor/punchly-sounds.js` is the checked-in runtime loaded by the static page. UISFX licenses ship with the bundle. [`package.json`](https://github.com/Arvind595/Punchly/blob/3a430e74f62595f8dbdbb25f19d7e8fb59c410ef/package.json) · [Browser bundle script](https://github.com/Arvind595/Punchly/blob/3a430e74f62595f8dbdbb25f19d7e8fb59c410ef/index.html#L643) · [`UISFX-LICENSE.txt`](https://github.com/Arvind595/Punchly/blob/3a430e74f62595f8dbdbb25f19d7e8fb59c410ef/vendor/UISFX-LICENSE.txt) · [`UISFX-LICENSE-AUDIO.txt`](https://github.com/Arvind595/Punchly/blob/3a430e74f62595f8dbdbb25f19d7e8fb59c410ef/vendor/UISFX-LICENSE-AUDIO.txt)
- **Runtime.** A trusted user gesture unlocks the audio context. Work cues follow the current day period and use saved master volume. Typing feedback is opt-in, and long-running export feedback can stop on navigation or teardown. - **Regression coverage.** The initial sound tests use a controlled runtime for gesture handling, cue playback and lifecycle. Use that test source to see which edge cases were already covered at v23. [`ui-sounds.test.mjs`](https://github.com/Arvind595/Punchly/blob/3a430e74f62595f8dbdbb25f19d7e8fb59c410ef/tests/ui-sounds.test.mjs)

## v24 · First punch day type and setup refinements

**Evidence.** v24 release notes are retained with v25. - **First-punch dispatch.** `requestFirstPunch` can open a day-type choice before today's first punch. A full or half day starts a draft, while leave or holiday saves without a start punch. ## v25 · Compact default and install fallback

The stored preference remains user-editable in Appearance. Browser installation and file fallback both route through the app's install logic. [Installation flow](https://github.com/Arvind595/Punchly/blob/8d5b2fc4a775f35056a19b742e716e66c61d7ac3/js/app.js#L397) · [Settings install action](https://github.com/Arvind595/Punchly/blob/8d5b2fc4a775f35056a19b742e716e66c61d7ac3/index.html#L389)

**Trace onboarding.** Start at `Storage.needsSetup`, follow `Setup.connect` and its completion callback, then inspect `requestFirstPunch` separately. Setup persists preferences, while the first-punch dialog changes the state of a specific shift. v32 adds the dedicated completion screen.
